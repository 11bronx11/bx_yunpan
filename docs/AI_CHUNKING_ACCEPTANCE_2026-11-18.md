# 父子切片修复与验收（2026-11-18）

基线为 `d7d3a3e` 的当前工作区。本轮只修改父子切片、共享切片辅助函数及旧版本 embedding 输入兼容逻辑；此前 Query / Ask 审计的未提交修改予以保留。

## 已复现的问题

1. v3 父片之间没有重叠。无标点长文在 1,600 个估算 tokens 附近硬切时，中文“预算”、较长中文短语、全角文字、罕见汉字及英文单词都可能没有一个完整的可检索子片。真实 PostgreSQL 的发布视图查询也复现了正文边界词零命中。
2. 表格超长单行拆分使用零重叠，同一单元格内的连续汉字双字项会丢失。2,000 个不同汉字组成的测试行，在旧实现字符索引 590 / 591 之间复现漏词；真实 PostgreSQL 查询也为零命中。
3. 旧子片重叠使用逐步扩大后缀、反复重新估算 token 的循环。在长空白后缀上会重复扫描同一段字符，存在平方级工作量。

复现日志：`artifacts/ai-chunk-audit-20261118/baseline.log`。该次基线执行时独立 ES 尚未就绪，其 `projection.unavailable` 不能作为 ES 功能复现证据；修复后的实际 ES 读取另行验收，禁止以 PG 回退冒充 ES 成功。

## 修复方式

- 新默认算法为 `parent-child-v4`。普通父片仍以 1,600 个估算 tokens 为目标，邻接父片共享最多 50 tokens 的连续原文；子片仍以 400 tokens 为目标，保留最多 50 tokens 的连续重叠。
- 表格仍以 600 tokens 为单片上限，重复携带表头；仅超长单行的继续拆分增加重叠，并保持同一真实行号。
- 重叠后缀改为单次反向计数。切片循环保留前进条件，长空白文本不会触发旧的反复后缀估算。
- source 仍保存规范原文块。重叠发生在 text 版本的检索窗口，不修改 source；摘要仍直接消费 source，不通过重叠父片拼接。
- 子片内容必须等于对应父片的 `ParentStart:ParentEnd` Unicode 字符切片；不编造 parser 没有提供的字节精度来源位置。
- 重叠不跨不同页码、标题或不兼容的 parser 原文块位置。表格保留 sheet、行列、表头，内容和位置随发布版本一起进入引用。

这仍是按结构和估算 token 切分，不是中文词法或模型语义切片。有限重叠保护边界附近的短词、短语，不承诺任意长查询或跨页面、跨章节查询都能在一个子片内全文匹配。

## 冻结版本兼容

保留 v1、v2、v3 的实现与接纳入口。修复前先记录固定输入的完整切片 JSON SHA-256，修复后逐一验证；这些快照覆盖正文边界、表格长行、单列表格、空块、ID、位置和 token 数。

v3 的 embedding 输入继续携带标题上下文，v1 / v2 继续使用原始子片正文。默认版本升级不会改变旧冻结任务的模型输入、哈希或子片 ID。parser 对 v1–v4 均只返回原文块，将父子切片留给内容 worker，不误用旧的 256 片平面切片限制。

## 运行与生效边界

本轮不部署应用、不修改用户 `.env`、不执行存量重建，不删除数据或卷。验收只使用既有专用测试数据库中的独立 schema、独立 ES 测试索引和测试进程；测试容器结束后恢复原启停状态。

部署新版并采用新 profile 后，新构建的 text 使用 v4。已发布 v3 内容不会被原地改写；要修复存量文件，需要按新版本重建 text、vectors 和对应投影，原 source 可以复用。已冻结旧任务继续按原版本执行。

父片重叠会增加少量索引内容与上下文重复，片段及 Ask 证据预算仍然生效。本轮验收不等于容量或高可用认证。
