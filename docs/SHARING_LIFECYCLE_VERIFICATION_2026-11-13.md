# 分享生命周期与删除并发验证（2026-11-13）

## 最终规则

- “我的分享”分为分享有效、分享过期、分享撤销、源文件已删除，服务端筛选，每页 10 条，使用游标前后翻页。
- 仅有效分享可以修改有效期或提前撤销。所选天数从本次保存时间重新计算；过期、撤销和源文件删除都不能通过修改有效期恢复。
- 分享创建时保存文件名、MIME 类型。历史展示直接读分享表，不再关联逻辑文件或物理对象，也不展示对象大小等存储信息。源文件后续改名不会改写这份历史快照。
- 状态互斥，优先级为源文件已删除、分享撤销、分享过期、分享有效。源文件被删除后，相关记录统一进入“源文件已删除”。
- 删除源文件会阻止后续分享访问和转存。已经转存成功的文件保留自己的逻辑文件与对象引用。
- 已授权的下载允许完成；到期、撤销或删除不会主动切断正在传输的连接。每个后续下载请求重新授权。

## 事务、锁与幂等

删除逻辑文件、标记所有关联分享的 `source_deleted_at`、推进版本、扣减对象引用和配额、写入删除/GC Outbox，均在同一个 PostgreSQL 事务内。失败则整体回滚。源文件和分享记录使用同一个删除时间；分享历史快照不被覆盖。

创建、修改、撤销、转存与删除统一先锁源文件，再锁分享，随后按配额、权限版本、对象的顺序加锁，避免删除新增分享更新后出现反向等待。单纯访问使用短事务持有分享共享锁，与修改、撤销和删除标记排出先后，流式下载不持有长事务。

有效期以 PostgreSQL 时间判断，使用 `clock_timestamp()`，避免事务开始时间被冻结或 API 副本时钟不同。管理操作在源文件、分享及权限版本行的锁等待结束后重新判断，更新 SQL 也带有效期条件。修改有效期保留版本号校验；过期、撤销、源文件删除统一返回 `409 share.inactive`。

重复或并发删除已经删除的同一逻辑文件返回成功，不再扣减引用/配额、推进分享版本或重复写删除事件。未删除文件的旧版本仍返回冲突，跨用户删除仍返回不存在。

## 迁移 000032

新增 `shares.file_name`、`mime_type`、`source_deleted_at`，回填已有分享的名称、类型和源文件删除状态。移除分享到源逻辑文件的外键，保留不可变 `file_entry_id` 作为关联删除时的来源标识。新增来源查找及所有者游标分页索引。

分享历史不持有物理对象引用，不阻碍正常 GC。源文件物理记录被清除后，历史仍可读取。回退到 31 会恢复原外键；若升级后已经物理清除了源记录但仍保留分享历史，需要先处理这些历史关联，不能直接回退。
