# 缓存优化说明

## 项目现状

网盘的目录和文件信息属于可重建读模型；权限、文件可见性、内容版本仍以 PostgreSQL 为准。当前缓存由进程内 L1、Redis L2 和 PostgreSQL 回源组成，缓存键带 owner 的内容/ACL 版本。缓存用于减少目录、文件查询开销，不负责授权。

## 本次改进

- **TTL 随机抖动**：缓存过期时间在配置 TTL 的 ±20% 范围内随机，分散一批热点数据同时过期造成的回源峰值。L1 命中时间不会超过 Redis 中剩余的 TTL。
- **跨实例热点合并**：同一缓存键在 Redis miss 时竞争短 lease；成功填充后，其他 API 实例可读取同一份结果。等待最长 40ms，超时就回 PostgreSQL，避免为等锁拖长请求。
- **Redis 熔断**：Redis 错误达到项目滑动窗口阈值后暂时跳过 Redis，继续使用本地 L1；L1 miss 则直接回 PostgreSQL。熔断器会半开探测 Redis 是否恢复。
- **安全释放 lease**：用持有者 token 校验后再释放，避免较早的加载任务误删新持有者的锁；解锁有独立短超时，不被业务熔断拦截。
- **避免重复回源**：数据库 loader 已经失败时，直接返回原始错误，不再由 service 立即重复执行同一查询。
- **增加监控**：新增 Redis 熔断状态和熔断跳过次数指标，并保留已有缓存命中、回源、Redis 错误和 L1 淘汰指标。
- **目录查询并发保护**：每个 API 进程的目录分页并发上限取 PostgreSQL 连接上限的一半（默认 16）。超过上限时立即返回 `503` 和 `Retry-After: 1`，不在应用层继续排队；低于上限时不增加等待。该限制只作用于目录列表，给其他读写接口保留连接预算。

## 未采用的处理

没有缓存“不存在”或“无权限”的结果。当前读取路径仍需 PostgreSQL 校验 owner、文件状态和版本；负缓存省不掉这些权威查询，还可能让新建或恢复的对象短暂误报不存在。本次并发上限只保护目录列表，不是全站限流，也不提供按用户的请求配额。

Redis 不可用时允许回 PostgreSQL，是缓存层降级，不代表 PostgreSQL 故障时可以返回旧的私有元数据。授权和版本检查失败时仍按原业务错误处理。

## 验证范围

已通过后端全量测试、缓存与 drive race 测试、`go vet ./...` 和 `git diff --check`。本说明对应代码实现和本地测试，不代表已部署到 staging/production，也不构成容量或跨主机故障认证。
